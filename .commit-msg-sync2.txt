fix: profile-sync-repair now checks MikroTik PPP secret profile directly

The repair service was only checking radusergroup in the RADIUS database.
If the RADIUS tables were correct but the MikroTik PPP secret profile was
still 'isolir', the repair skipped the user — leaving them stuck.

Now the repair also fetches PPP secrets from MikroTik via the API and
compares the profile. If the MikroTik profile is 'isolir' or mismatched,
it fixes both the RADIUS tables and the MikroTik PPP secret, then kicks
the active session.
