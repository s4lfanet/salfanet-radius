fix: rekap voucher period filter defaults to most recent batch date

When switching to daily/weekly/monthly filter, the default period was
always the current date/month. If no vouchers existed in the current
period, the page showed no data and the filter appeared broken.

Now the frontend tracks the most recent batch date from the "all data"
view and defaults to that period when switching to a period mode. This
way, the user immediately sees data when switching to monthly/weekly/daily.

Also removed debug logging from the rekap voucher API route.
